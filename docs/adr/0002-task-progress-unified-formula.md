# 任务进度统一为"耗时完成度"公式

任务的进度**永远是**"耗时完成度"：已完成工作量 / 总工作量。一条公式，两种数据源——有子目标时分子是已完成子目标的预计耗时之和；无子目标时分子是用户汇报百分比 × 总耗时。

考虑过的备选：让无子目标任务直接用"用户输入百分比"作为进度，而不映射到耗时。否决理由：这导致同一份 UI 要渲染两种意义的进度（子目标驱动的"4/5" vs 用户手动报的"60%"），且"今日推进"工作量计算需要再做一次耗时换算。把百分比强制映射回耗时之后，UI 和工作日算法都只对"已耗时 / 总耗时"这一个数。

后果：用户汇报无子目标任务的"完成 60%"时，前端仍要传 0.6，但展示层统一渲染为"已完成 X 小时 / Y 小时"。不能跳过耗时映射。
