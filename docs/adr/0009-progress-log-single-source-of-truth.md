# 进度汇报以事件日志为单一事实源

每次汇报追加一条进度事件（任务、时刻、增量分钟、来源），任务当前进度、今日完成量、今日总结、工时账户结算**全部从事件日志派生**，不固化任何汇总表。今日总结弹出后内容仍随后续汇报实时变化（不重弹，控制面板可重看），次日的"昨日总结"补登同理由此免费获得。

考虑过的备选：① 任务表只存当前进度字段——否决：无法回答"今天推进了多少"，达标判定、均分、总结全部失据；② 每日一条的快照表——否决：日内多次汇报仍需合并逻辑，修正历史时快照与事实脱节。

后果：无子目标任务的汇报是增量语义（每次 +X%）；"改口"通过任务详情的"修正总进度"实现（同样以事件形式落账）；一切按日统计的口径统一为"事件时刻归属其工作窗口**开始日**"（跨午夜窗口的归属）。
