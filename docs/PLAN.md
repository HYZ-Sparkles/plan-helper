# Plan Helper（桌面任务伴侣）

## 1. 目标与范围

### 1.1 核心目标

解决"约定 3 天都完不成任务"的拖延问题。具体效果:

- 用户给出一周 / 一月 / 年度计划后,系统自动拆解并排程到每日
- 桌宠常驻桌面,以温柔治愈的方式陪伴并鼓励用户完成每日任务
- 用户不汇报 = 自动标未完成,允许手动加班补救;第二天依旧未完成才触发动态调整算法把未完成的工作量分摊到未来 N 天,使用户"被推回正轨"而不是"被放弃"

### 1.2 In scope

- Tauri 桌面应用(Windows 优先,代码层面预留跨平台)
- Live2D 桌宠(透明窗口、常驻桌面)
- 任务规划引擎:计划 → 任务 → 子目标,自动生成每日清单
- 三类鼓励触发:定时(A)/任务节点(C)/进度对比(E)
- 工作/休息模式自动切换(时间表 + 手动覆盖)
- 本地数据存储(SQLite)
- LLM 云端 API 集成(DeepSeek + MiniMax,OpenAI 兼容协议)

### 1.3 Out of scope

- 云同步、多设备
- 应用签名、商店分发
- 移动端(iOS/Android)
- 商业化、用户运营、付费功能

## 2. 关键决策

### 2.1 产品定位

- 核心定位:**执行伴侣为主,科学规划为辅**
- 形态:桌宠(Live2D 拟人形象) + 桌面小组件
- 用户体验基调:温柔治愈,不强制、不打扰、不评判

### 2.2 技术栈

- 桌面框架:**Tauri**(Rust 后端 + Web 前端)
- 前端框架:**Vue 3 + TypeScript**(用户熟悉,便于审查 AI 代码;AI 生成 Vue 3 代码可靠性更高)
- 本地存储:SQLite(rusqlite 或 sqlx)
- Live2D 渲染:Cubism Web Framework(`@live2d/cubismwebframework`)
- LLM 客户端:`reqwest` 调 OpenAI 兼容 API
- 默认模型:**Live2D 官方 Natori**(免费、可商用)

### 2.3 鼓励机制

- 触发方式:
  - A 定时:每 N 分钟一句(Week 1-3 不开,Week 4+ 按需开启)
  - C 任务节点:**默认开启**,场景为任务开始 / 过半 / 临近 deadline / 超期 / 放弃
  - E 进度对比:v2.0
- 任务完成反馈:鼓励语 + 今日完成数(如"3/8 完成~")
- 放弃/超期:**桌宠不评判、不主动安慰**,由动态调整算法接手
- 0 完成日:今日小结气泡**不弹出**(静默)
- 鼓励语料池:Week 3 先 10 条覆盖核心场景,Week 4+ 扩到 30-50 条
- 气泡停留时间:5 秒自动消失,**不重复提醒**

### 2.4 工作 / 休息模式

- 切换机制:**时间表为骨 + 手动覆盖为补丁**
- 时间表:用户在设置里配置每周工作时间(如"周一到周五 9:00-12:00, 14:00-18:00")
- 手动覆盖:点击桌宠选择"切换模式"按钮，那么会工作模式和休息模式转换。按照工作时间的不同桌宠挂的牌子也不同
  - 工作时间下休息模式："今日摸鱼"
  - 非工作时间下工作模式
    - 当天任务未完成： "今日加班"
    - 当天任务完成了： "超前完成！"
- 非工作时间手动开启工作模式的状态显示与鼓励:
  - 当天任务未完成 → 显示"加班";当天任务已完成 → 显示"超前"
  - 特殊鼓励机制:加班时温柔托底、不评判;超前时惊喜夸赞
- 工作时间段启动:桌宠切"工作装"(戴眼镜/拿笔) + 气泡提示(5 秒消失,工作时间段内不重复提醒)
- 工作时间段结束:桌宠切回"休息装" + 今日小结气泡(5 秒消失)
- 休息模式下:桌宠**自顾自做自己的事**(看书/打盹/喝咖啡循环动画),**不冒任何闲聊**
- 跨边界情况:**沉默为主、明示边界、绝不打扰心流**
- 法定假日:首次启动时让用户填节假日,默认全天休息,手动按钮可覆盖

### 2.5 科学规划引擎

- 计划输入:结构化任务清单(任务名 / 估时 / 优先级 1-5 / 同级排序号 / 截止日 / 依赖关系可选)
- 任务结构:**三层**——计划(Plan) → 任务(Task) → 子目标(Subtask)
- 子目标来源(任务级选择):
  - ✍️ **手动列**:用户直接列出所有子目标
  - 🤖 **AI 拆**:用户写详细描述,LLM 拆分
- AI 拆分处理:**二次确认 + 编辑**(LLM 返回结果先预览,用户可增删改任意子目标,确认后进入排程)
- LLM 集成:**云端 API**,OpenAI 兼容协议,默认支持 DeepSeek + MiniMax,**用户自配 API key + base_url**
- 任务先后关系:**优先级 1-5 + 同优先级内手动排序号**(不做完整 DAG 依赖图)
- 排程算法:按"优先级降序 → 同优先级内按排序号升序 → 截止日升序"排列所有子目标,然后按估时均匀填入每日可用工作时间
- 动态调整算法:**智能重排 + 宽松度滑块**
  - 重排窗口:默认 7 天(激进 5 / 平衡 7 / 宽松 14)
  - 每天工作量上限:默认 8 小时
  - 触发时机:工作时间段结束时仅标 🔴,不重排;次日开工前扫描依旧未完成的子目标才触发智能重排(给手动"加班"留出补救窗口)
  - 未汇报子目标自动标 🔴
  - 排不下的任务按优先级推迟或提示用户
- 手动汇报:
  - ✓ 完成:点一下即可
  - 🚧 进行中:可选拖进度条 0-100%
  - 🔴 放弃/卡住:点一下 + 可选 50 字内备注
- **不汇报 = 自动标 🔴 未完成**(无打扰,无弹窗)

### 2.6 桌宠形象与人设

- 形象类型:**拟人角色**(Live2D 二次元)
- 模型策略:**单一默认 + 支持导入自定义**(需做适配层)
- 默认模型:Natori(Live2D 官方免费)
- 人设策略:**单一默认 + 高级自定义**
- 模型与人设**脱耦**:模型=视觉,人设=性格/称呼/口癖(软件配置,不绑定模型)
- 默认人设:**"温柔学姐 · 默"**
  - 性别:女
  - 年龄感:大 1-2 岁的学姐
  - 性格:温柔治愈(不督促、不指责、永远托底)
  - 称呼:用户的名字(首次启动填写)或回退到"你"
  - 口癖:偶尔"嘛"、"哦"、"呢",不堆叠
- 高级自定义范围:性格(4 选 1)、称呼、口癖开关、性别(需换模型,默认锁定)

### 2.7 小组件

- 展示内容:**极简三件套**——当前子目标 + 今日完成数 + 工作时间结束倒计时
- 交互:子目标默认折叠 1 行;点击左侧按钮看完整清单;点击子目标可进行汇报:完成/进行中(XX%)/卡住/放弃
- 可拖动到屏幕任意位置

### 2.8 数据存储

- 模式:**全本地**(SQLite)
- 路径:`%APPDATA%/plan-helper/data.db`
- 自动备份:每周打包到 `backups/data-YYYYMMDD.zip`,保留最近 4 周
- 手动导出/导入:JSON 格式,导入时让用户选"覆盖"或"合并"
- 损坏恢复:启动时检测数据库损坏 → 自动从最近备份恢复 + 提示用户

## 4. 实施步骤

### 4.1 Week 1:能存能读(任务清单 + SQLite)

本阶段建立项目骨架和数据层,让用户能在 Tauri 桌面应用里增删改查任务。本阶段不涉及任何花哨的东西,目标是让用户看到"我能造一个能存数据的应用"的成就感。

先用 `npm create tauri-app@latest plan-helper` 创建 Tauri 项目(选 **Vue + TypeScript** 模板),放在项目根目录。然后用 `sqlx` 或 `rusqlite` 初始化 SQLite,建三张表 `plans` / `tasks` / `subtasks`,分别存计划元数据、任务清单、子目标清单。表结构要预留排程和动态调整算法所需的字段(`subtasks.status`、`subtasks.scheduled_date`、`subtasks.estimated_minutes`、`subtasks.order_index`、`subtasks.priority` 等)。然后前端做一个极简任务清单界面:输入框 + 估时输入 + 优先级下拉 + 列表展示,所有增删改查通过 Tauri `invoke` 调到 Rust 后端读写 SQLite。

完成后启动应用应能输入任务、刷新页面后任务仍在。**这是后续所有功能的前提,必须先完成。**

### 4.2 Week 2-3:让桌宠上场(透明窗口 + Live2D)

本阶段把桌宠这个"情感核心"做出来——透明窗口 + Live2D 模型加载 + 可拖拽。完成后用户第一次看到自己写的桌宠在桌面上动起来,是整个项目的"惊喜时刻"。

Week 2 先在 Tauri 里创建透明无边框窗口(`tauri.conf.json` 中 `transparent: true`、`decorations: false`),加载一个最小化 Web 页面专门渲染 Live2D。集成 Cubism Web Framework(通过 npm 包),加载 Natori 模型到 `src/assets/live2d/natori/` 目录,实现基本渲染后加上鼠标拖拽(监听 `mousedown`/`mousemove` 计算偏移量,调 `window.setPosition`)和"窗口置顶"(`window.setAlwaysOnTop(true)`)。Week 2 末尾处理跨 DPI 适配(监听 `devicePixelRatio` 变化),否则桌宠在 4K 屏上会模糊。这一阶段桌宠暂不接业务逻辑,只做"能显示、能动、能拖"。

Week 3 接入业务逻辑。先做小组件面板:基于 Week 1 的任务清单界面,做"极简三件套"小组件(当前子目标 + 今日完成数 + 工作时间结束倒计时),默认折叠成一行,可拖动。然后做手动汇报:子目标上点 ✓ 调 Rust 后端改 `subtasks.status = 'completed'`,同步更新小组件的今日完成数。接着做任务完成反馈:完成时触发桌宠切到"开心"动作 + 气泡显示鼓励语 + 今日完成数(如"3/8 完成~"),鼓励语料池先写 10 条。最后做工作/休息模式基础切换:用 Rust `tokio` 定时器检测当前是否在工作时间段,控制桌宠"工作装/休息装"切换 + 启动/收工气泡。

**Week 3 末尾用户应能体验完整的核心闭环——这是产品的灵魂时刻。**

### 4.3 Week 4:智能功能(排程 + LLM + 动态调整)

本阶段给科学规划引擎加上"智能"部分:排程算法 + LLM 集成 + 动态调整。这些功能让产品从"手动工具"升级为"自动化助手"。

先做排程算法(Rust 后端):写一个 `scheduler` 模块,输入是计划下的所有任务 + 子目标 + 用户的工作时间段配置,输出是每个子目标的 `scheduled_date`。算法按"优先级降序 → 同优先级内按排序号升序 → 截止日升序"排列所有子目标,然后按估时均匀填入每日可用工作时间。这一步不接 UI,只在 Tauri 命令里暴露 `regenerate_schedule` 供后续调用。

然后做 LLM 集成(Rust 后端):写 `llm` 模块用 `reqwest` 调 DeepSeek / MiniMax 的 OpenAI 兼容 API(用户在设置里填 API key + base_url)。提示词明确告诉 LLM"你是一个任务拆解助手,把任务描述拆成 3-8 个可执行子目标,每个含 name / estimatedMinutes / order",输出约束为 JSON。前端做"AI 拆解"按钮:点了调 LLM,返回结果先进入二次确认界面(左边 LLM 原始结果、右边可编辑表格),用户点"采用"才进入排程。

最后做动态调整算法:每天工作时间段结束时扫描所有未汇报的子目标(自动标 🔴 未完成),允许用户手动加班补救;次日开工前依旧未完成的触发智能重排。重排窗口默认 7 天、每天上限 8h、排不下按优先级推迟或弹气泡提示用户。宽松度滑块(激进 5 / 平衡 7 / 宽松 14)放在设置里。

### 4.4 Week 5+:按需扩展(不预判)

Week 5 之后**不再预判需求**。根据用户实际使用两周后的反馈决定加什么:用户发现某些任务手动列子目标太累 → 优先做 LLM 智能拆的 UI;用腻 Natori → 做自定义模型导入;想看到自己变好 → 做进度对比(E 鼓励)的细化。

每个新功能单独评估工作量,不复用"必须 6 周内完成"的压力。项目节奏从"赶 MVP"变成"养工具"。
