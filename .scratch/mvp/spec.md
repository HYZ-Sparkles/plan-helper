# Spec：Plan Helper MVP（计划模块 + 桌宠模块）

Status: ready-for-agent

> 词汇与规则以仓库根 `CONTEXT.md` 与 `docs/adr/` 为准；本 spec 不重复论证，只合成。

## Problem Statement

我立下的具体大目标（如"备考英语 6 级"）总是烂尾：目标太大不会拆解、每天该推进多少没有数、连续没达标也没有任何机制把我拉回来。纸面 to-do 没有工作量概念，通用工具没有"计划→任务→子目标"这种带预计耗时与顺序的建模，更没有一个每天陪着我、提醒我今天该干什么完成得怎么样的角色。

## Solution

一个桌面任务伙伴（Tauri 桌面应用）：**Oreo Cat 桌宠**常驻桌面，配上**计划系统**——计划拆成一次性的任务、任务细化为有序子目标；每个工作日开始时在大面板选择今日推进的任务（硬约束：选中任务的累计预计耗时 ≥ 当日实际目标）；按子目标勾选或百分比增量汇报进度；每日差额（未达标上调、超额下调）进入**工时账户**按工作日均分，目标透明显示、欠债跟着走；更高优先级计划开始时低优先级自动暂停（抢占不变式），保证专注；工作日结束自动弹出今日总结。桌宠在工作模式安静陪伴，休息模式玩耍卖萌。

## User Stories

### 计划创建与编辑

1. 作为用户，我想要创建计划（名称、简述默认同名、纯文本详细内容、优先级默认 Medium、可选截止日期仅作展示），以便把大目标落成结构化记录
2. 作为用户，我想要单页可折叠表单（Plan 段默认展开，Task / SubGoal 段默认折叠、按段独立校验），以便看到全貌、随时回头修改，而不是被向导锁死
3. 作为用户，我想要在任务卡上填名称、简述（默认同名）、详细内容，并切换"是否需要子目标"，以便按任务复杂度决定汇报方式
4. 作为用户，无子目标的任务被要求必填预计耗时，以便进度与工作量有换算基准
5. 作为用户，我想要子目标精简输入行（内容 + 预计耗时，回车自动加行聚焦），以便流式连续录入
6. 作为用户，子目标顺序 = 填写顺序且不可拖拽，以便顺序语义稳定（未完成的一律排在已完成之后）
7. 作为用户，我想要在任务卡上从同计划任务中多选"前置任务"（轻量收进展开态次要区域，创建表单与详情编辑态都提供），以便表达 A→B 的硬依赖
8. 作为用户，保存时计划必须至少 1 个任务、勾了子目标的任务必须至少 1 个子目标，以便不留空壳
9. 作为用户，我想要给进行中的计划追加新任务（排在所有未完成任务之后），以便补上中途发现的遗漏
10. 作为用户，我想要修改未完成任务/子目标的字段与顺序，以便纠偏；已完成的锁定不可改
11. 作为用户，我想要删除任务永远可点但走确认弹窗（显示将丢失的进度、必须打字"再删"），以便防误删；删除是软删除进归档
12. 作为用户，计划开始后优先级不允许调整，以便制定时认真（专注的根基）

### 状态机与抢占

13. 作为用户，计划状态沿单向瀑布流转（未开始→进行中→已暂停/已完成/已放弃，已暂停↔进行中），已完成/已放弃是终态，以便历史不被污染
14. 作为用户，我想要在控制面板开始/停止计划，以便自主掌控节奏
15. 作为用户，存在进行中的更高优先级计划时低优先级计划的「开始」被禁用并说明原因，以便抢占不变式（进行中必然同等级）始终成立
16. 作为用户，更高优先级计划开始时我手头进行中的低优先级计划自动暂停（暂停原因记"自动抢占"），以便专注高优先级
17. 作为用户，我可以主动暂停计划（原因记"用户主动"），以便给低优先级计划让路，或在不宣告失败的情况下停放计划
18. 作为用户，当不存在进行中的更高等级计划时（含完成、放弃、手动暂停之后），等级最高的"自动抢占"组整组自动恢复、逐层向下，用户主动暂停的永不自动恢复，以便回到被打断前的节奏而无需手动记账
19. 作为用户，被恢复的计划若再遇更高等级开始会再次被抢占，以便规则始终如一
20. 作为用户，任务进度到 100% 自动转已完成；所有任务完成后计划停留在"进行中"并亮起「完成计划」按钮，我点击确认后才进入"已完成"，以便保留"我做到了"的确认感
21. 作为用户，我想要放弃计划（二级确认、打字"再删"），以便诚实承认失败且历史可查
22. 作为用户，我想要对终态计划"复制并新建"（复制名称/详细内容/优先级/截止日期/任务与子目标、进度归零、名称加"- 副本"、直接进入进行中），以便低成本重启

### 今日分配（大面板）

23. 作为用户，处于工作模式且今日未分配时大面板自动打开（工作窗口开始时 / 手动切入工作模式时 / 启动序列完成后检测），以便每天有个明确的开始
24. 作为用户，大面板显示所有进行中计划（必然同等级）并按计划分组，以便一眼看到可推进的全集
25. 作为用户，前置任务未完成的任务不出现在大面板（只展示可选任务，2026-08-24 修订——原"置灰显示等待：任务A"砍掉），以便依赖清晰可见
26. 作为用户，勾选任务时底部状态条实时累计预计耗时（"今日累计 X.X 小时 / 当日实际目标 Y 小时（基准 + 结转）"），以便对照目标选量
27. 作为用户，累计低于目标时看到黄色差额软提示、超出时无警告、任何情况都不被阻止提交，以便"推进是硬约束、完成是柔性"落到实处
28. 作为用户，点底部中间「确认」关闭大面板完成当日分配，以便开始干活
29. 作为用户，我想要在控制面板重开大面板调整当日选择（已推进的进度保留），以便应对计划变化

### 汇报与进度

30. 作为用户，小看板显示当前任务（所属计划、任务名、当前待完成子目标或百分比控件），以便随手推进
31. 作为用户，我从今日推进列表手动指定当前任务；「更换任务」时同计划的备选排在前面，以便减少跨计划的突兀感
32. 作为用户，有子目标的任务按序勾选推进（最小单位 1 个、不可跳序），以便汇报变成勾清单
33. 作为用户，无子目标任务用百分比控件汇报（[-] -10%、点数字直填 5% 倍数、[+] +10%，默认 5%，会话级不持久化），以便长任务也能一次推进更大比例
34. 作为用户，百分比汇报是增量（每次 +X%），一切进度与统计从 ProgressLog 派生，以便"今天做了多少"永远有据可查
35. 作为用户，我想要撤销已完成子目标的勾选（toast 提示"进度已重算"），以便手滑可救
36. 作为用户，我想要在任务详情里"修正总进度"（直接设定当前值、带确认；已完成任务锁定），以便改口不走日常汇报路径
37. 作为用户，当前任务完成后小看板空态停留（"✓ 任务完成" + 「更换任务」），以便由我决定下一步而不是被自动切换
38. 作为用户，修改预计耗时或增删未完成子目标时进度按已完成分钟数自动缩放，以便派生公式始终自洽
39. 作为用户，小看板底部常驻今日总量微型进度条（今日推进 X / 调整后目标 Y），以便随时知道离目标多远

### 工时账户

40. 作为用户，某工作日未达标（低于调整后目标 -10% 容差），差额按均分窗口向后续工作日均分上调目标，以便债跟着走而不是消失
41. 作为用户，实际完成超额时对称抵扣（后续每日目标下调），多劳真的能换来之后的轻松；而选择层面的超额（选了 14h 只推 5h）不抵扣
42. 作为用户，多日差额滚动叠加（当日实际目标 = 基准 + Σ 各差额均分到今天的份额），均分目标日再未达标则递归再均分，以便账户始终诚实
43. 作为用户，大面板与今日总结透明显示调整后目标并标注结转（"目标 5.6h（基准 5.0h + 结转 0.6h）"），以便不疑惑"目标怎么变了"
44. 作为用户，历史修正（撤销子目标、修正总进度）后受影响日期与未来全部目标实时重算，以便日志是唯一真相、不存在两本账
45. 作为用户，非工作日的推进照常记任务进度并按超额入账，以便临时加干不算白干
46. 作为用户，假期提前用日期例外排除出工作日、而不是事后清账（不设清账操作），以便规划在前、监督在后

### 工作时间与今日总结

47. 作为用户，我配置每日工作时间、每周工作日、日内多段时间窗口（如 10:00–11:30, 20:00–22:00），以便贴合真实作息
48. 作为用户，我在周循环之上按日期双向覆盖（"这天不工作"假期 / "这天工作"调休），以便长假与补班都可表达
49. 作为用户，工作时间/工作日/窗口改动自下一个工作日生效（均分窗口立即生效），以便当日判定不失去基准
50. 作为用户，最晚工作窗口结束那一刻自动弹出今日总结；当天没开应用则次日首开弹"昨日总结"补登，以便每天有账可对
51. 作为用户，总结只弹一次，内容随后续进展实时重算、可在控制面板随时调出，以便晚上加干也能对上账
52. 作为用户，总结顶部是总览行（推进计划数 / 完成 X 小时 / 目标 Y 小时 / 进度条），下方按"计划→任务→推进内容"三层嵌套，被抢占暂停的计划照常展示并标注、其推进计入达标判定，以便干了的活不被谎报
53. 作为用户，总结中提示"有更高优先级计划未开始"，以便不忘主次
54. 作为用户，跨午夜的工作窗口（如 20:00–01:00）内汇报与总结都归属窗口开始日的工作日，以便凌晨干活不撕裂账本

### 控制面板

55. 作为用户，控制面板侧边栏固定三项（计划管理 / 创建 / 设置），以便功能各就各位不迷路
56. 作为用户，"计划管理"用状态筛选栏（全部 / 未开始 / 进行中 / 已暂停 / 已完成 / 已放弃，各带数量）展示单列表，默认"全部"，以便五个状态都是一等公民、随时俯瞰全局（2026-08-23 grill 修订，取代 4-tab）
56a. 作为用户，我想从计划管理点击计划卡进入**计划详情页**（头部：字段+状态+生命周期操作+「编辑」；正文：任务列表→子目标层级），以便查看与修改计划内容；编辑态复用创建表单组件（双模式），生命周期按钮不进编辑态
56b. 作为用户，我想让任务卡默认收起为一行摘要（名称 + 耗时/子目标标记），点行展开完整字段，以便创建页紧凑、长字段不占常驻空间（2026-08-24 修订：砍掉原"拖拽排序"——任务顺序 = 创建顺序不可拖，先后语义唯一归依赖边，同 57 砍计划手动排序的原则；同日复审砍掉序号标识——偏序任务贴全序编号必然误导，顺序关系改由详情页"前置/被等待"双向行承载）
57. 作为用户，计划列表按优先级降序 + 创建时间倒序自动排序，以便优先级与新近度自动组织列表（2026-08-24 修订：原"可拖拽手动覆盖并持久化"砍掉——实施顺序在大面板自主选择、优先级制约，列表手动序无意义；拖拽交互保留给任务卡，连续流动式）
58. 作为用户，今日总结作为"计划管理"页的小栏目/按钮可随时点开，以便回看历史总结
59. 作为用户，无计划时"计划管理"页给"创建第一个计划"空状态引导，以便第一次打开不茫然
60. 作为用户，首次启动无向导、默认值直进（5h/天、周一至五、均分窗口 7 工作日），以便零配置即可用

### 桌宠

61. 作为用户，启动时桌宠播放启动序列（21 Ear Up→22 Scan→23 Ear Down→24 Jump out→7 Stand Idle），期间交互禁用，以便每天有个可爱的开场
62. 作为用户，工作模式桌宠 Sleep Idle 安静陪伴；休息模式随机动作（吃:跳:闲坐 = 4:3:3，上次动作结束起 300 秒间隔），以便陪伴不打扰
63. 作为用户，点击桌宠弹出菜单（控制面板 / 切换模式 / 再见），模式切换有过渡动画（4 Stand to Sleep / 6 Sleep to Stand），以便掌控但不割裂
64. 作为用户，用户触发的动作独占当前动作锁（播放中按钮禁用 + tooltip，拖拽与菜单查看不受影响），系统随机动作不占锁，以便动作不叠加、体验流畅
65. 作为用户，拖动桌宠不打断动画、拖完在休息模式下先起身再 Attack；桌宠可拖到屏幕任意位置（任务栏禁入、不出物理边界、多显示器可跨、靠边 <20px 吸附），以便随手整理桌面
66. 作为用户，小看板与桌宠一起拖动、但桌宠动作不带动看板，位置联动而动作独立
67. 作为用户，休息模式隐藏小看板、切回工作模式恢复，以便休息就是休息
68. 作为用户，退出走桌宠菜单「再见」或托盘「退出」，桌宠播放跳入箱子动画后关闭全部窗口；桌宠窗口无关闭按钮、系统关闭被拦截；控制面板/大面板/小看板关闭只是隐藏，以便告别有仪式、误关不伤身
69. 作为用户，系统托盘常驻（左键打开控制面板，右键菜单：打开控制面板/退出），以便桌宠被挡住时也有入口

### 视觉

70. 作为用户，全应用走线条 + 暖色基调（1px 边框、极浅填充、暖橙主色），禁用 emoji、统一 Phosphor 图标（regular 为主），优先级用"文字标签 + CaretUp/Minus/CaretDown"，以便界面克制精致、与桌宠的可爱形成刚柔对照
71. 作为用户，桌宠保持像素 Oreo Cat 原生视觉不被 UI 风格同化，以便它是角色而不是组件

## Implementation Decisions

- **技术栈**（README 既定）：Tauri（Rust 后端 + Web 前端）、Vue 3 + TypeScript、SQLite（rusqlite）。
- **架构分层**：领域核心（状态机、抢占不变式、工时账户、依赖闭包、今日分配、ProgressLog 结算）实现为**不依赖窗口、时钟注入的 Rust 领域服务层**；Tauri command 是薄代理；Vue 前端是纯 UI 壳，不做业务判断。
- **接缝（本 spec 唯一自动化验证接缝）**：Rust 领域服务层——全部自动化测试打在这里。
- **遵循的 ADR**：[0001] 计划状态机单向瀑布；[0002] 进度统一耗时完成度公式；[0005] 线条 + 暖色视觉基调（含 DesignTokens）；[0006] 抢占不变式；[0007] 工时账户对称均分；[0008] 任务顺序硬依赖边；[0009] ProgressLog 单一事实源。
- **数据决策**：
  - `ProgressLog` 追加式（任务、时刻、增量分钟、来源：子目标/百分比/修正），任务当前进度、每日完成量、工时账户结转、调整后目标**全部实时派生、不固化**。
  - 任务持有**前置依赖**（仅同计划内；删除前置自动解除依赖）；无子目标任务持有预计耗时；子目标持有预计耗时且二态。
  - 计划持有 `pause_reason`（自动抢占/用户主动）；终态不可逆；"复制并新建"是唯一重启路径。
  - 每日一份**今日分配**记录（日期 + 选中任务集），可覆盖重选；当日已推进从日志来、与选择无关。
  - **设置**：每日工作时间、每周工作日、日内多段窗口、日期例外（双向覆盖）、均分窗口（工作日数）。生效时机按 SettingsEffectiveTime。
  - 软删除：任务删除与计划放弃都进归档可查，不物理删除。
- **窗口体系**：桌宠、小看板（置顶、无边框，桌宠无关闭按钮且拦截系统关闭）、大面板、控制面板（普通窗口，关闭即隐藏）+ 系统托盘。桌宠与小看板共享坐标、动作独立。
- **时间语义**：所有按日统计以"工作窗口开始日"归属（跨午夜安全）；"今日是否工作" = 周循环 + 日期例外合并判定。
- **桌宠动作执行**：当前动作锁模型（见 CONTEXT.md PetActionExecution）；随机动作权重与间隔硬编码于 PetConfig，无配置 UI。
- **默认值**：工作时间 5h/天、工作日周一至五、均分窗口 7 个工作日、无子目标任务单次推荐百分比 5%、新计划优先级 Medium。

## Testing Decisions

- **只测外部行为**：给领域服务输入命令（开始计划、汇报、确认分配……），断言可观察输出（状态、事件、派生数值）；不测内部结构与私有函数。
- **接缝唯一**：Rust 集成测试覆盖领域服务层；时钟注入使"今天/窗口边界/跨午夜/次日补登"全部可确定性测试。
- **必测规则清单**：状态机全转换与非法转换拒绝；抢占不变式（开始禁用、自动暂停、逐层恢复、再抢占、手动暂停不自动恢复）；依赖闭包与解除；今日分配硬约束与状态条数值；工时账户（对称抵扣、滚动叠加、递归均分、±10% 容差按调整后目标、历史修正实时重算、非工作日超额入账）；任务 100% 自动完成与计划手动确认；删除/放弃的确认流；复制并新建的归零。
- **UI 与桌宠动画不在自动化范围**：每张实施工单自带手动验收步骤（布局、拖拽、动画衔接、托盘行为）。
- **先例**：无（本 feature 是代码库第一个，本 spec 建立测试先例）；测试注释按仓库规范写明"测试什么情况、什么结果才算正确"。
