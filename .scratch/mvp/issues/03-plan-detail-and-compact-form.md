# 03: 计划详情页与表单紧凑化

**What to build:** 计划管理页结构重组：状态筛选栏（全部/未开始/进行中/已暂停/已完成/已放弃 + 数量，默认"全部"）替代 4-tab；点击计划卡进入**计划详情页**（头部：计划字段+优先级标签+状态徽章+生命周期按钮占位（05 接线）+「编辑」；正文：任务列表）。「编辑」把正文切成编辑态——**复用创建表单组件（创建/编辑双模式）**；创建表单同时紧凑化：任务卡默认收起为一行摘要（拖拽手柄 + 名称 + 预计耗时/子目标标记），点行展开完整字段，长字段只在展开态。任务拖拽排序（创建与编辑同一交互）、未完成任务字段编辑、进行中追加任务、软删除任务。

背景：spec 用户故事 2、9–11、56、56a、56b；术语 PlanManagementView / PlanDetail / CreationUI（双模式+任务卡形态）；2026-08-23 grill 决策（用户否决 4-tab 与主从布局，详情走独立整页——计划少而任务/子目标多）。

### 验收反馈修正（2026-08-24，第一轮手动验收）

- 拖拽不动：Windows WebView2 下 Tauri 默认 OS 级拖放拦截吞掉 HTML5 dragover/drop → control-panel 窗口 `dragDropEnabled: false`（需完全重启 dev 生效）；另加拖拽落点高亮（目标卡边框亮主色）。
- 布局空旷：三页内容列改居中限宽（表单/详情 720px、计划列表 840px，窄窗口自动收缩）——用户确认方案。
- 截止日期原生控件占位"YYYY/MM/日"（浏览器内置改不掉）：改文本输入 + `isValidDateString` 失焦校验——用户确认方案。
- 详情页空字段显示"（未填写）"廉价 + 简述=名称重复：空字段整行隐藏、简述与名称相同不显示（列表卡同规则）——用户确认方案。

### 验收反馈修正（2026-08-24，第二轮手动验收）

- 拖拽修复已验证通过。
- 日期输入仍不友好 + 错误红字顶歪字段对齐：联网调研成熟库（@vuepic/vue-datepicker 体积 +100KB 起、v-calendar 偏日历展示）后用户选定**自制月历弹层**（`DatePicker.vue`，零依赖 +10KB，工单 13 日期例外复用）；手打三格式归一（`normalizeDateString`），非法失焦回退，不再有错误红字。
- 对齐修复：计划字段行（优先级+截止日期）改顶部对齐、分段控件与输入框等高（min-height 36px）——错误/高度差不再挤歪旁边字段。

### 验收反馈修正（2026-08-24，第三轮手动验收）

- 日期框仍偏高且不对齐：`.input` 无 border-box，DatePicker 里的 `min-height: 36px` 落在内容区上实际约 52px → 删除该 min-height；计划字段行内两控件改为显式 `height: 36px; box-sizing: border-box` 严格等高。
- 校验机制漏洞：打字中间态垃圾直接进表单值、失焦非法时只回退了显示没回退数据（垃圾会随保存落库）→ DatePicker 维护 lastValid，失焦非法时**表单值与显示一并回退**；空输入=清除；弹层锚点先归一（垃圾不再算出 NaN 月历）；buildDraft 边界兜底 `normalizeDateString`（垃圾归 null）。
